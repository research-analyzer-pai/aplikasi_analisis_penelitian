# v3.1 AI Research Studio — scope and safeguards

## API design
- Uses OpenAI Responses API over HTTPS.
- User supplies API key and triggers each request explicitly.
- Requests set `store: false`; this does not replace the user's obligation to review provider data controls, account retention settings, institutional policy, and consent/ethics requirements.
- No key is written to source files or the ZIP package.
- The app does not store API conversations in its own database.
- Inputs are sent to the external provider. Never submit identifiable participant data, confidential unpublished material, or protected data without appropriate authorization.

## Six task workflows
1. Article analysis.
2. Theory comparison.
3. Candidate research-gap identification.
4. Draft instrument development.
5. Preliminary transcript analysis.
6. Discussion drafting based only on supplied findings and references.

## Evidence integrity
Prompts instruct the model not to invent citations, DOI, quotes, findings, or numeric results. This instruction reduces risk but does not guarantee perfect compliance. Researchers must verify all output. Article analysis is limited to extracted text; scanned PDFs may yield little/no text. The app does not perform systematic web/database searches, retrieve full-text articles, validate peer-review status, or verify references.

## Researcher responsibility
AI outputs are advisory drafts. Validate theory fit, source evidence, research design, instrument content, coding decisions, and interpretations. Protect participant confidentiality and comply with research ethics and applicable institutional rules.

## Technical test status
Unit tests cover request payload formation, output parsing, task validation, missing-key handling, and input-size limits. They do not test a real API call, model availability, billing, or research validity.
