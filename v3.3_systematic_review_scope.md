# v3.3 systematic-review workflow: scope and cautions

## Import
RIS and BibTeX importers support common export patterns and common bibliographic fields. They are not complete parsers for every vendor-specific dialect. Inspect record counts and fields after import. CSV import expects column names compatible with the review matrix.

## Duplicate detection
Likely duplicates are flagged using exact normalized DOI or normalized title. This can miss near-duplicates and can falsely flag distinct records with identical titles. Review every duplicate decision before removal from the final PRISMA accounting.

## Screening
Each unique record can receive title/abstract and full-text decisions. Reasons and reviewer notes can be captured. This release does not implement independent dual screening, blind reviewer conflict resolution, or automated full-text retrieval.

## PRISMA-style accounting
Counts are computed from imported records and reviewer decisions. The Mermaid diagram is an editable flow representation, not a complete PRISMA 2020 flow diagram template. Confirm the flow against the review protocol and applicable PRISMA checklist. Search methods, dates, databases, registers, other sources, automation tools, reports, studies, and exclusion reasons may require additional reporting fields depending on review type.

## No automatic quality appraisal
The application does not assess risk of bias or certainty of evidence. Use design-appropriate validated tools and report decisions transparently.
